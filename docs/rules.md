## 1. How to Use This Document

This document defines the binding architectural, clinical safety, UX, data modeling, and engineering rules for the Recollect platform.

* Rules marked **[HARD]** are non-negotiable. They protect senior cognitive safety, clinical accuracy, and offline resilience. Violating a **[HARD]** rule breaks system compliance.
* Rules marked **[GUIDANCE]** represent strong design and engineering defaults that require documented justification before deviation.
* Every feature in the prototype and any future production evolution must be verified against the checklist in **Section 10**.

## 2. Non-Negotiable Product, Clinical Safety & Ethical Rules

Recollect operates directly alongside seniors experiencing Phase-1 cognitive impairment (Mild Cognitive Impairment / Early Dementia) and their caregivers. These rules enforce strict medical ethics and psychological safety.

* **[HARD] Zero Diagnostic or Curative Claims Anywhere:**
  * No copy, button, tooltip, report, audio script, or log may claim or imply that the app diagnoses dementia, assesses clinical disease stages, or provides medical therapy.
  * **❌ Strictly Prohibited:** *"Dementia score"*, *"Cognitive failure"*, *"Stage 1 Dementia Confirmed"*, *"Your memory is getting worse"*, *"Diagnosis report"*.
  * **✅ Mandatory Approved Framing:** *"Pattern observed"*, *"Gentle routine reminder"*, *"Engagement trend"*, *"Worth discussing with your doctor"*, *"Supporting daily routine"*.
* **[HARD] Every AI & Rule-Generated Flag Must Be Fully Explainable:**
  * Any `BehaviorFlag` generated by the rule engine must carry inspectable, human-readable evidence pointing directly to raw timestamps, latency figures, or session counts (`BehaviorFlag.evidence`).
  * Black-box numbers, unexplainable risk scores, or ungrounded machine learning flags are strictly prohibited.
* **[HARD] Human-in-the-Loop on Every AI Output:**
  * Clinicians and caregivers must always have the power to **Confirm**, **Dismiss as Noise**, or **Add Clinical Notes** to any behavioral flag. No automated action (such as dispatching emergency responders) may occur without human review, except explicit SOS button presses.
* **[HARD] Mandatory In-App Disclaimers:**
  * **Composite Weekly Score:** Must display:  
    > *"This score reflects engagement and activity trends. It is not a medical diagnosis. Please consult your doctor about any concerns."*
  * **Cognitive Mind Games:** Must display:  
    > *"Supportive engagement tool, not a clinical treatment or diagnostic device."*
  * **Clinical & ASHA Hub:** Must display:  
    > *"Mandatory Clinical Advisory: This platform is an assistive cognitive engagement and routine monitoring decision-support tool. It does not independently diagnose dementia, stage disease severity, or provide clinical treatments."*
* **[HARD] Positive-Reinforcement Only in Cognitive Feedback & Score Tracking:**
  * Mind games must run in an edge-to-edge full-screen environment (`100vw` × `100vh`) with dedicated "Pause & Rest" exit buttons.
  * Mind games must never display negative feedback, red "WRONG" alerts, failure buzzers, or countdown clocks.
  * The patient-facing score tracker must present strictly encouraging metrics: cumulative **Garden Stars (⭐)**, positive session points (75–100 pts), and blooming stages (🌱 -> 🌻). Raw error stats and latency numbers must never be exposed directly to the senior.
  * Silent clinical telemetry (`hesitation_avg_ms`, error counts, duration) is strictly isolated to backend stores (`GameSession`, `CaregiverActivityLog`, `RuleEngine`) for caregiver and clinician visibility only.

## 3. Client-Side, Local-First & Prototype Architecture Rules

These rules enforce offline resilience and define the concrete operational boundary between the client-side prototype and production extensions.

* **[HARD] 100% Offline Core Functionality:**
  * All senior interactions—routine reminders, pill confirmations, audio narration, mind games, mood check-ins, and text scaling—must function completely offline with zero network connectivity.
  * Network latency must never block a patient-facing screen or interaction.
* **[HARD] Local-First Storage Priority (`RecollectDB`):**
  * All user writes persist immediately to client-side storage (`localStorage` with prefix `recollect_db_`) before any synchronization is attempted.
* **[HARD] Append-Only Immutability for Clinical Logs:**
  * Tables recording patient behavior (`ReminderLog`, `GameSession`, `MoodLog`, `CaregiverActivityLog`) are append-only. Once recorded, records are never mutated or overwritten.
* **[HARD] Cloud-Authoritative Reminders with Live Client Authoring:**
  * Scheduled routines are defined by caregivers and synced to the tablet.
  * In the prototype, caregivers can author custom reminders (**"➕ Add Task"**) and delete custom tasks directly within the portal, seamlessly coexisting with baseline routines.
* **[HARD] Silent Sync Failures for Seniors, Transparent for Caregivers:**
  * The Senior Patient Space must never display network errors, spinners, or technical connection warnings.
  * The Caregiver Portal must prominently surface sync recency via the **Hub Sync Badge** (e.g., *"Live Hub Sync: 9:02 AM"*).
* **[GUIDANCE] Prototype vs. Production System Boundaries:**
  * **Prototype Implementation:**
    * Client-side architecture using HTML5, CSS3, and ES6+ JavaScript modules.
    * Client-side database (`RecollectDB`) operating in `localStorage`.
    * Local voice synthesis via `SpeechSynthesis` with Web Audio API pentatonic chime fallback.
    * Simulated interactive phone calling overlay with timer and pulse.
    * Simulated SMS/USSD fallback and in-app doctor/ASHA messaging with automated replies.
    * Native `@media print` engine for generating the 7-section clinical PDF report.
    * Ayushman Bharat ABHA referral packet and DPDP/GDPR JSON export generators.
  * **Production Extensions (Future Scale):**
    * Multi-device synchronization over secure WebSocket / HTTPS REST endpoints.
    * Live telephony gateway (e.g., Twilio / National Health SMS Gateway).
    * Production ABDM Sandbox M1/M2/M3 API certification.
    * WebRTC real-time peer-to-peer audio/video calling.

All modules must strictly conform to the entities and field names established in `js/db.js`:

```
+-----------------------------------------------------------------------------+

+----------------------+------------------------------------------------------+

| Reminder             | reminder_id, patient_id, type, label, instructions,  |
|                      | scheduled_time, pill_details, priority, active       |

|                      | ('acknowledged'|'dismissed'|'no_response'), timestamp|
| GameSession          | session_id, patient_id, category, pack_type, score,  |
|                      | hesitation_avg_ms, mistake_count, completed_at       |
| MoodLog              | log_id, patient_id, score (2–5), mood_label,         |

+----------------------+------------------------------------------------------+
```

* **[HARD] Mandatory Trend Instrumentation at Write Time:**
  * Every game session must capture `hesitation_avg_ms`, `mistake_count`, and completion duration at the moment of completion.
  * Every reminder acknowledgment must record the exact response timestamp and computed response latency.
* **[HARD] `BehaviorFlag.evidence` Field Integrity:**
  * Must never be null. It must contain quantitative evaluation parameters (e.g., consecutive misses, inactive hours, score drop percentage) and a plain-language summary.

## 5. Phase-1 Rule Engine & Clinical Telemetry Rules

The deterministic rule engine (`js/ruleEngine.js`) evaluates longitudinal behavior against strict, configurable clinical threshold constants:

```javascript
const RULE_CONFIG = {
  VERSION: 'rule_v1',
  MISSED_MEDICATION_WATCH_STREAK: 3,
  MISSED_MEDICATION_ALERT_STREAK: 5,
  INACTIVITY_WATCH_HOURS: 48,
  INACTIVITY_ALERT_HOURS: 96,
  SCORE_DECLINE_PERCENT_THRESHOLD: 0.25,
  SCORE_DECLINE_CONSECUTIVE_SESSIONS: 3,
  LATENCY_SPIKE_MULTIPLIER: 2.0
};
```

* **[HARD] Rule A: Missed Reminders Streak:**
  * Evaluates consecutive unacknowledged medication logs.
  * $\ge 3$ consecutive misses triggers `severity: 'watch'`.
  * $\ge 5$ consecutive misses triggers `severity: 'alert'`.
* **[HARD] Rule B: Inactivity Gap:**
  * Evaluates elapsed time since the last recorded interaction (game or reminder).
  * $\ge 48$ hours triggers `severity: 'watch'`.
  * $\ge 96$ hours triggers `severity: 'alert'`.
* **[HARD] Rule C: Game Score Decline:**
  * Evaluates recent 3 sessions against a 14-day historical baseline.
  * $\ge 25\%$ performance drop triggers `severity: 'watch'`.
* **[HARD] Rule D: Response Latency Spike:**
  * Compares recent touch hesitation against the historical rolling baseline.
  * Latency $\ge 2.0\times$ baseline triggers `severity: 'watch'`.
* **[HARD] Composite Weekly Score Algorithm:**
  $$\text{Composite Score} = (0.40 \times \text{Adherence \%}) + (0.40 \times \text{Game Accuracy}) + (0.20 \times \text{Engagement Frequency})$$
  * Yields a normalized score between 0 and 100.
  * Accompanied by mandatory non-diagnostic footnote across all displays.

## 6. Escalation, Calling & Emergency Rules

* **[HARD] 5-Minute Escalation Target Window:**
  * When a critical medication reminder remains unconfirmed, the Caregiver Portal displays the high-priority **Overdue Routine Alert Banner**.
  * Provides instant actions: *Call Eleanor's Tablet*, *Mark Taken by Caregiver*, and *Test SMS/USSD Fallback*.
  * Hides dynamically the moment the senior or caregiver confirms the routine.
* **[HARD] Multi-Tier Emergency Escalation ("🚨 Call Help"):**
  * **Primary Contact:** Immediate high-priority notification to Sarah Vance.
  * **Secondary Contact:** Standby queue dispatch to Priya Vance (+91 98765 43211).
  * **Emergency Helpline:** Direct 1-tap dialer link to the **112** National Emergency Helpline.
  * Every emergency activation must write an audit record to `CaregiverActivityLog`.

## 7. UX, Accessibility, Themes & Automated Scheduling Rules

* **[HARD] Senior Typography Floor (20pt Minimum):**
  * Normal mode enforces a strict 20pt base floor.
  * Large mode scales to 24pt (+20%).
  * Extra Large mode scales to 28pt (+40%) for low vision.
  * Quick-cycle button available on the bedside tablet orientation bar.
* **[HARD] Touch Target Minimums:**
  * Minimum hitbox of `56px × 56px` across all buttons and interactive elements. Primary patient action buttons must measure `64px–72px`.
* **[HARD] Single-Decision Orientation (One Action Per Screen):**
  * Seniors are presented with one primary decision at a time.
  * The full-screen attention takeover provides exactly three vertically stacked choices: **"✓ Done"**, **"⏰ Remind me in 10 minutes"**, and **"🤝 Need help from Sarah"**.
* **[HARD] Dark Mode (Calm Night Theme):**
  * Deep slate palette (`#0b1329` / `#111e3e`) with high-contrast text (`#f1f5f9`), reducing glare and eye strain for seniors during nighttime hours.
* **[HARD] WCAG AAA High-Contrast Stark Mode:**
  * Pure black-on-white theme with 3px solid borders, stripping all decorative colors and shadows.
* **[HARD] Password-Gated Theme Management (PIN `1234`):**
  * Both Dark Mode and High-Contrast toggles, along with their automated scheduling controls, must be secured inside the Caregiver Settings modal behind the Caregiver PIN (`1234`).
  * Seniors must never be able to accidentally disrupt their visual environment from the bedside tablet.
* **[HARD] Automated Theme Scheduling:**
  * Caregivers can configure custom start and end time windows for both Dark Mode and High-Contrast Mode.
  * The application orientation loop must evaluate the active schedule every 30 seconds and automatically apply the appropriate theme without page reloads.
  * Must support time windows spanning midnight (e.g., 20:00 to 07:00).
* **[HARD] Low-Power & Reduced Animation Mode:**
  * Suppresses non-essential transitions and background animations to conserve battery life on low-cost hardware.

## 8. Regional Localization Rules (Northeast India Focus)

* **[HARD] 5 Supported Regional Languages:**
  * **English (`en`)**
  * **Assamese (`as`)** — অসমীয়া
  * **Bengali (`bn`)** — বাংলা
  * **Khasi (`kha`)** — Khasi (Meghalaya)
  * **Hindi (`hi`)** — हिन्दी
* **[HARD] 100% UI String Coverage:**
  * Every heading, button, card, modal, placeholder, tooltip, and SVG label must use `data-i18n` attributes mapped to `RECOLLECT_I18N`.
* **[HARD] Regional Calendar & Date Localization:**
  * Dates must be formatted using native regional day and month names via `getFormattedDate()`.
* **[HARD] Audio Narration & Calming Chime Fallback:**
  * Spoken briefing uses `SpeechSynthesis` with calm pacing (`rate = 0.85`, `pitch = 1.05`) mapped to BCP-47 regional voices.
  * If speech synthesis is unavailable or offline, the system must automatically play a 5-note pentatonic chime progression (C4–C5) via the Web Audio API.
